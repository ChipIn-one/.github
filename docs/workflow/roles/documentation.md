# Documentation contract

When behavior, UI, UX, commands, contracts, or workflow change, update the target repository's canonical user documentation in the same revision as defined by its `AGENTS.md` and `.ai/context.md`.

For changes that do not affect user-facing behavior or workflow, record the applicable documentation decision in the task approval/handoff. Do not create extra documentation files when an existing canonical document should be updated.

Role and workflow files, repository instructions, context files, and historical design records are process material rather than user guides. Keep repository-specific documentation policy in the owning repository. This canon does not replace that policy.
